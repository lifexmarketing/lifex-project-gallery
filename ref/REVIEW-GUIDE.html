What we're evaluating

Tussey's Photo Gallery is currently run by an outside vendor's script (hosted on a third-party domain we don't control). Tussey's Project Gallery runs on an aging in-house plugin. The proposal is to build one clean, in-house gallery system that serves both, improves local SEO, runs fast and light, and removes the outside dependency. The prototype shows the visitor experience and the team's tagging workflow; the docs lay out the plan, the developer spec, and how we'll test it.

The key decisions so far

  • Build standalone, in-house. A new, cleanly-built gallery rather than extending the old code, so we don't risk the live project gallery and we own the whole thing.
  • Photos stay as tagged images. Each photo carries its own category, sub-tags, town, alt text, and caption — so the sales team can filter, and each photo also works for local search.
  • Two-tier tags, matching the live site. Main category, then sub-tags (e.g., hardscape → patio, walkway, fireplace…). The full tag list was pulled from the current gallery.
  • One engine, two galleries. The Photo Gallery uses sub-tag filtering; the Project Gallery uses category + town, exactly as each works today.
  • Leave the vendor cleanly. We confirmed we can migrate the whole photo catalog without needing the outside vendor's account.
  • Fix the old plugin too. The existing project-gallery plugin has security, performance, and PHP issues; the plan hardens it on staging before any cutover.

Where we'd value your perspective

1. Look & feel / UX

Does the gallery look and behave the way it should for a Tussey visitor on desktop and phone? Is the filtering obvious and fast? Anything about the layout, lightbox, or styling that feels off or could be better?

2. Tags & categories

Are the main categories and sub-tags right? Anything mislabeled, missing, or that the sales team would want renamed? In Project Gallery, do the projects land in the right categories? (Heads up: project categories are currently inferred from each project's title — see caveats.)

3. Scope & approach

Does building standalone, hardening the old plugin, and migrating off the outside vendor feel like the right call? Any concerns about effort, timeline, or risk to the live site we should weigh?

4. Local SEO strategy

Will the category + town + per-photo approach actually help Tussey show up for local searches (e.g., "patio installation State College PA")? Anything we're over- or under-investing in? Thoughts on which category/town pages are worth publishing first?

Known caveats (so you don't have to flag these)

  • The prototype pulls live images from Tussey's servers, so it needs an internet connection and the images load as-is.
  • The Photo Gallery sample is 15 photos; categories like pools and lighting show as tags but have no sample photos yet, so they'll show an empty state.
  • The Project Gallery uses 23 real projects; each opens to its cover photo with a link to the full project page (we only pulled covers for the demo).
  • Project categories are inferred from project titles in the prototype; the real build will use the actual category data.
  • This is a front-end prototype to react to, not the finished plugin.
